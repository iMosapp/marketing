### Safeguards confirmed on real data
- Field shapes unchanged: 0 list fields changed item type (strings stay strings, kids keep their dicts).
- Nothing erased: projection only `$set`s; traded / bought-elsewhere never blank a legacy field (the fact store carries the truth).
- Unverified never overwrites verified: AI guesses without a quote on identity-like keys wait as proposed/disputed; older records land as historical.
- Free-text lead comments are the driving signal but never become `vehicle_interest` (25 contacts would have been hit before the fix).
- Appraisal records are probable, unconfirmed ownership: medium confidence, `confirmations 0`, listed to verify, excluded from `vehicle_purchased`, and 68 repeated appraisal rows only corroborate. A rep confirming on the vehicle page (or a sale) flips it.
- Store / tenant isolation: all backfilled facts carry the contact's store; another org's admin gets 404; managers' dry runs are scoped to their store.
- Campaigns, enrollments, conversations, tasks, notifications: never written by the engine (fingerprint test J13 + validation suite).

## Defects found while running against real preview data (all fixed, all covered by tests)
1. `inbound_leads.inquiry` is a structured block, not a string -> backfill crashed on the first lead.
2. Projection changed legacy list shapes (strings -> `{label}` dicts) and copied lead comments into `vehicle_interest`.
3. Soft-deleted vehicles (111 of Sarah's) were planned as ownership.
4. Appraisal records counted as human-verified ownership (would have projected 9 unconfirmed vehicles).
5. Reaffirmations were not idempotent (a second backfill pass re-added evidence and confirmations).
6. Repeated system records inflated `confirmations` (69 appraisal rows looked like 68 confirmations).
7. Projection output was read back as legacy evidence on the next pass (feedback loop).
8. Rollback left `null` keys unset (semantically equal, not byte-exact).
9. Lead labels carried the widget's newline + "(From https://...)" suffix.
10. `/facts/suggest`, `/confirm`, `/dispute` did not re-project (found by the testing agent).

- Felix, F-150 inquiry then "we ended up buying a truck from another dealer": intent closed as lost, record kept; topic "They bought elsewhere; stay the trusted contact"; opening "Hi Felix, congrats on the new ride! No pitch here..."; evidence = the text + the lead.

- Hank, appraisal on his brother's Civic: topic "Confirm they still own the 2015 Honda Civic EX" (unverified ownership); after the rep disputes: nothing owned, record kept as disputed, `vehicle_purchased` never written.
- Victor, rep typed "Sarah", voice note says "Karen", AI guesses "Donna": Karen current (newer, quoted, same reliability), Sarah superseded (kept), Donna disputed and listed for a human.

What is and is not proven: topic / why / opening / evidence are deterministic (built in code from the facts, Layer E base). The GPT phrasing layer that turns them into the rep's voice is a later phase and was not part of this validation.

## Remaining risks
- Dry run after projection over-approximates "would change" for already-backfilled contacts (1 cosmetic case, Sally Tester); run the dry run before the backfill.
- Legacy mirror fields are never blanked, so after a trade `vehicle_purchased` still shows the traded vehicle until the UI reads the fact store.
- The legacy lead-intake code still writes comment text into `vehicle_interest` by itself for new leads (pre-existing behaviour, untouched).
- "Not shopping" and "bought elsewhere" detection is English regex; a scored LLM signal is not used for those two decisions yet.
- Production numbers are unknown until the production dry run (read-only, safe) is executed.
- No rep-facing UI for facts yet; reps see no change.
