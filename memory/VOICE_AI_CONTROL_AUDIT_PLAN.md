## B. Recommended implementation (phased, each phase independently testable in preview)

### Phase 2: policy model + allowances (backend)
- New collections: `voice_policies` (one per org: `enabled`, `premium_engine` live, `backup_engine` mini, `per_user_daily_premium_min` 15, `account_daily_premium_min`, `account_monthly_premium_min`, `monthly_budget_usd`, `soft_warn_pcts` [80], `hard_premium_cap_usd`, backup safeguards `per_user_daily_backup_min` 60 + `account_monthly_backup_usd`, `carry_over` false, `plan_key` standard|pro|unlimited (Phase 9), `product`), `voice_user_overrides` (per user: `daily_premium_min`, `extra_minutes[]` grants with grantor/expiry, `premium_disabled`, notes), global safety doc `settings.voice_ai_global` (absolute per-user/day ceiling, kill switch, pricing table with "verified on" date).
- `services/voice_policy.resolve(user)` -> effective allowance with the precedence **global safety -> account budget/shared caps -> user override -> account default**; a user override never exceeds an account hard cap unless the override carries `super_admin_authorized=True`.
- Day boundary: the **account's** configured time zone (`organizations.timezone`, falling back to the current user chain) at midnight; carry-over off by default.
- Accounts not enrolled (`enabled=false` or no policy) keep today's behaviour byte for byte (existing global caps path untouched).

### Phase 3 + 4: server-authoritative metering, reservations, fallback (backend + app)
- `voice_usage_ledger`: one row per **segment** (`org_id, user_id, live_id, segment_no, engine, model, started_at, ended_at, billable_s, tokens, est_cost_usd, actual_cost_usd (null until reconciled), cost_basis provider_usage|client_report|estimate, fallback_reason, thresholds_hit[], device_id, reconnect_of, admin_override_id, error`). `live_sessions` keeps the session record and gains `org_id`, `segments[]`, `enforcement`.
- `voice_reservations`: one doc per user per local day with atomic `$inc` + conditional filters: a session must **reserve** premium seconds in 60-second slices before they are spent; two simultaneous sessions share one pool, so the second device cannot double the allowance. Unused slices are released on close.
- Server sideband (`services/voice_meter.py`): on session start the backend attaches to the OpenAI session (Live `/attach`, Realtime `?call_id=`), records authoritative seconds/tokens into the ledger every slice, and when the premium pool hits zero sends `session.close` (Live) / hangup (Realtime) with reason `premium_cap`. Client reports stay as a fallback cost basis (labelled) when the sideband is unavailable. Hard $ caps are checked on the same tick: never a silent premium second past a hard cap.
- Fallback = reconnect with context: the app receives `session.closed`/`premium_cap` -> immediately calls `POST /live-voice/session {resume_from: live_id}` -> backend builds the backup session seeded with the last ~40 transcript turns (<= 8,192 tokens), same personality/instructions, pending confirmations, walkthrough position, and a one-line optional spoken bridge ("continuing with Jessi's standard voice experience"), never framed as an error. If the backup refuses (503), the existing graceful "Jessi is resting" path. Backup minutes have their own per-user and per-account safeguards (no unlimited fallback).
- App change needed (EAS): `useLiveJessi` handles the server-initiated handoff (reconnect, keep the mic track, show the small toast). Old app versions keep working: the server still stops premium at the cap and they see today's cap message.

### Phase 5: AI Voice Control Center (Super Admin panel section)
Overview tiles (sessions today, premium/backup minutes, est. spend today / month / projected, users at limit, accounts near budget), searchable accounts table (name, active users, premium/backup minutes, est. monthly cost, avg daily, allowance, budget status) -> account page (users, overrides, grants, policy editor), Power User Leaderboard (total/premium/backup minutes, sessions, avg length, days active, est. cost, limit-hit frequency; today / 7d / 30d / custom). Reuses Voice Lab session list and styles.

### Phase 6: Power User Insights
Nightly job flags users on configurable thresholds (10+ min/day, 5+ sessions/week, cap reached 3+ days/week, top 10% by minutes). Panel: account + user, usage history, most-used voice features (from `delegations[].tool`), last active, trend, est. cost, internal notes, follow-up status. "Request feedback" creates an internal task (existing `tasks`) for the account owner / super admin with the five questions; **no automatic outreach**.

### Phase 7: alerts
Deduped per day/threshold: user 80% / 100% (-> backup), account 80% of monthly budget, account premium cap reached, daily spike (> 3x trailing 7-day mean), repeated sessions (> N starts/hour), backup spend over threshold. Delivered through the existing Super Admin Alerts (`notifications`), optional push/email via the existing helpers.

### Phase 8: tests (pytest, live preview API with a `VOICE_FAKE_PROVIDER=1` test switch so no audio or OpenAI spend is needed)
The required list maps 1:1: 15-minute cap -> backup; backup continues; midnight reset in account tz; override; account cap precedence; two simultaneous sessions share one pool; context seeded on fallback; disconnect mid-transition; backup 503 -> graceful; admin change during an active session applies at the next slice; ledger/cost accuracy; cross-account isolation (403); non-enrolled account unchanged (existing `live_voice` tests still pass). Plus one real audited session per engine in preview to confirm sideband seconds match the client.

### Phase 9: monetization-ready, not active
`plan_key` + `plan_catalog` doc (standard 15, pro 30, unlimited with fair-use + spend guard, minute bundles as `extra_minutes` grants with `source: purchase`) and a `voice_entitlements` hook; no Stripe products, no purchases.

## C. Cost estimation methodology (labelled on every number)
- Premium (GPT-Live): `max(15, provider_seconds) x $0.05 / 60` from the sideband/`session.closed` seconds (basis `provider_usage`); client seconds only as fallback (basis `client_report`).
- Backup (Realtime mini): provider `response.done` token usage x verified price table; add `gpt-4o-mini-transcribe` input tokens (to add to the table) so backup is not under-estimated.
- Delegation brain: tokens from the backend LLM calls priced separately and shown as "backend AI (est.)".
- "Actual" only after reconciliation against the OpenAI invoice / Costs API for the period (monthly manual step unless the key gets `organization.costs.read`); until then everything is "estimated".
- Pricing table lives in `settings.voice_ai_global.pricing` with a "verified on" date and is shown in the dashboard.

## D. Rollout and rollback
Preview with the Lab flag + per-account `enabled=false` default -> founder walkthrough -> explicit GO -> Save to GitHub -> Deploy (backend + web) -> smoke -> `eas update` (handoff UX) -> enrol one account at a time. Rollback: feature flag off returns every account to today's path instantly; code rollback via checkpoint. New collections are additive.

## E. Scope and risks
- Scope: ~6 build sessions (P2 policy + P4 ledger/reservations: 2; P3 sideband + fallback incl. app: 1.5; P5 dashboard: 1.5; P6 + P7: 1; P8 tests/rollout: 1). Backend ~2.5k lines, app ~600 lines.
- Risks: (1) sideband availability/latency on Realtime calls and the exact hangup path (verify in preview first; fallback = client-driven stop + server refuses further premium reservations, which still prevents over-spend); (2) the fallback requires the app update for the seamless feel; (3) provider usage events arrive about once a minute on GPT-Live, so enforcement granularity is ~60 s (reserve slices sized accordingly); (4) OpenAI "actual cost" is only reconcilable per billing period, not per session; (5) time-zone edge cases around DST when a user and their account differ (account tz wins by rule).
