## 3. Required production configuration (check BEFORE deploy)
1. `TWILIO_WEBHOOK_VALIDATION` must be **unset or `enforce`** in production secrets (a leftover `log`/`off` would silently keep the hole). Emergency lever if legit callbacks are refused after deploy: set it to `log`, redeploy — no code change.
2. `PUBLIC_FACING_URL` / `APP_URL` = `https://app.imonsocial.com` exactly as the numbers are configured in Twilio (`/api/webhooks/twilio/incoming`). The validator also accepts the raw request URL and the forwarded host, so a mismatch here is logged as `[TwilioSig] ... signature mismatch`.
3. `TWILIO_AUTH_TOKEN` (parent) present (it is: SMS works); subaccount tokens come from the encrypted org record.
4. `RESEND_WEBHOOK_SECRET` (Resend > Webhooks > signing secret `whsec_...`) must be set in production or inbound email replies answer 503 until it is. Preview has it empty -> 503 by design.
5. No DB migration. No secret rotation. `SESSIONS_VALID_AFTER` from hotfix 2 stays as set (a future value is now harmless).
