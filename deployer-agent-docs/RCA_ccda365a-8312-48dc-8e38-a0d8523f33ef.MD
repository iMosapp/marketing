## Date-range counts — COULD NOT ANSWER (tool limitation, not guessing)
The mongo_query `filter` does NOT parse `{"$date": "..."}` extended JSON into a BSON Date; range comparisons against a date operand silently match nothing.
Proof (contact_events, where ALL 4,280 docs have a BSON-date `timestamp`: $type:date=4280, $type:string=0):
- `timestamp $lt {$date:"2100-01-01"}` → 0  (should be 4280)
- `timestamp $gte {$date:"2000-01-01"}` → 0  (should be 4280)
Both 0 is impossible for a working date filter. Same behavior on notifications.created_at.
Therefore:
- contact_events with BSON-date `timestamp` older than 2024-10-15 → UNANSWERABLE with this tool.
- notifications with BSON-date `created_at` older than 2026-07-17 → UNANSWERABLE with this tool.

Field-type breakdown that IS reliable (via $type, which works):
- contact_events: 4,280 total; timestamp BSON-date = 4,280; string = 0.
- notifications: 2,948 total; created_at BSON-date = 2,901; string = 47.
